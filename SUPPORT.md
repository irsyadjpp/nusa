# Support Policy

## Getting Help

NUSA Platform adalah proyek solo-developer open-source. Berikut adalah cara mendapatkan bantuan:

## 📞 Support Channels

### GitHub Issues (Recommended untuk Bug Reports)
- **URL**: https://github.com/sdibonerate85/nusa/issues
- **Best untuk**: Bug reports, feature requests, technical issues
- **Response Time**: 1-3 hari kerja
- **Format**: Gunakan issue template yang tersedia

### GitHub Discussions (Recommended untuk Pertanyaan)
- **URL**: https://github.com/sdibonerate85/nusa/discussions
- **Best untuk**: Pertanyaan umum, diskusi teknis, best practices
- **Response Time**: 1-5 hari kerja
- **Format**: Bebas, tapi gunakan judul yang deskriptif

### Documentation
- **README.md**: Quick start dan overview
- **docs/**: Comprehensive architecture dan implementation docs
- **CODE_OF_CONDUCT.md**: Community guidelines
- **CONTRIBUTING.md**: Development guidelines

## 🎯 Support Scope

### What I Can Help With

#### Bug Fixes
- Bug yang reproducible di environment saya
- Issue dengan setup dan installation
- Error yang clear dan actionable
- Problem dengan integrasi standard

#### Technical Questions
- Architecture dan design decisions
- How-to questions tentang fitur yang ada
- Best practices untuk menggunakan NUSA
- Questions tentang Kurikulum Merdeka implementation

#### Feature Requests
- Fitur yang align dengan roadmap
- Improvement yang feasible untuk solo maintainer
- Suggestions yang konkret dengan use case jelas

### What I Cannot Help With

#### Outside Scope
- Custom development untuk specific school
- Integration dengan third-party systems yang tidak standard
- Consulting atau professional services
- 24/7 production support
- SLA-based support

#### Complex Customization
- Heavy customization yang memerlukan significant refactoring
- Fitur yang bertentangan dengan architecture freeze
- Changes yang tidak align dengan Kurikulum Merdeka
- Implementation teknologi yang di-luar tech stack

#### Training dan Onboarding
- Training untuk teachers atau admin
- Onboarding untuk new developers di organization Anda
- Workshop atau seminar
- Consulting untuk deployment strategy

## ⏱️ Response Time Expectations

Sebagai solo maintainer dengan full-time job lain:

| Issue Type | Initial Response | Resolution Time |
|------------|-----------------|-----------------|
| Critical Bug (security, data loss) | 1-2 hari | 3-7 hari |
| High Priority Bug | 2-3 hari | 1-2 minggu |
| Normal Bug | 3-5 hari | 2-4 minggu |
| Feature Request | 5-7 hari | Roadmap dependent |
| General Question | 3-5 hari | 1-2 hari (answer) |
| Documentation Request | 5-7 hari | 2-4 minggu |

### Factors That Affect Response Time

- Availability saya (full-time job lain, personal commitments)
- Complexity issue
- Number of pending issues
- Priority based pada impact
- Whether issue reproducible di environment saya

## 🐛 Reporting Issues Effectively

### Bug Report Checklist

Sebelum report bug, pastikan:

- [ ] Saya sudah cek existing issues untuk duplikat
- [ ] Saya sudah cek dokumentasi untuk solusi
- [ ] Bug masih reproducible di latest version
- [ ] Saya bisa provide steps to reproduce yang jelas
- [ ] Saya bisa provide environment details
- [ ] Saya bisa provide logs/error messages

### Good Bug Report

```markdown
## Description
Brief description of the bug

## Steps to Reproduce
1. Go to '...'
2. Click on '....'
3. Scroll down to '....'
4. See error

## Expected Behavior
A clear and concise description of what you expected to happen.

## Actual Behavior
What actually happened

## Environment
- OS: [e.g. Ubuntu 22.04]
- Browser: [e.g. Chrome 120]
- Backend Version: [e.g. 0.3.0]
- Frontend Version: [e.g. 0.3.0]
- Database: [e.g. PostgreSQL 18.4]

## Logs/Screenshots
[Add relevant logs or screenshots]

## Additional Context
[Any other context about the problem]
```

## 💡 Feature Requests

### Feature Request Guidelines

Saya menerima feature request tapi:

1. **Alignment**: Harus align dengan Kurikulum Merdeka domain
2. **Feasibility**: Harus feasible untuk solo maintainer
3. **Roadmap**: Priority berdasarkan roadmap dan impact
4. **Implementation**: Provide concrete use case dan expected behavior

### Feature Request Template

```markdown
## Problem Statement
What problem does this feature solve?

## Proposed Solution
How do you think this should be implemented?

## Alternatives Considered
What other ways did you consider?

## Additional Context
Why is this feature important to you?
How would it benefit the education community?
```

## 🔒 Privacy and Data

### Support Communication

- Saya tidak akan meminta sensitive data (passwords, API keys, personal student data)
- Jangan share logs yang mengandung real student/teacher data
- Sanitize data sebelum share di public channels

### Safe Sharing

```bash
# Sebelum share logs, sanitize:
- Remove names (guna pseudonym)
- Remove email addresses
- Remove phone numbers
- Remove addresses
- Remove sensitive identifiers
```
